# Development

## Prerequisites

Enter the dev shell for the formatters and linters:

```bash
nix develop
```

It provides `nixfmt`, `statix` and `deadnix`.

## Formatting

```bash
nix fmt
```

## Add a custom theme

1. Create `dotfiles/themes/<Name>/theme.conf` (copy `Pwnbox` as a base).
2. Drop a wallpaper next to it.
3. `git add` the folder (the flake ignores untracked files), rebuild
   (`./scripts/install.sh switch`), then pick it from `ALT + S → Custom`.

Only `name`, `background` and `foreground` are required; everything else falls
back to the monochrome palette. See
[Themes](../usage/themes.md#custom-themes) and `dotfiles/themes/README.md`.

## Add a site theme

Site themes live in `dotfiles/zen/userstyles/` as compiled CSS templates with
`#f0f0xx` colour markers (see the `pwnbox-userstyles` section of
`dotfiles/scripts/pwnbox-theme` for the slot table):

1. Take a compiled usercss from
   [catppuccin/userstyles](https://github.com/catppuccin/userstyles) and adapt
   its palette to the marker slots.
2. Add it as `dotfiles/zen/userstyles/<name>.css`.
3. Rebuild; `pwnbox-theme` regenerates it with the active palette on every
   theme change and serves it for the pwnbox styles extension. Any leftover
   yellow/gold shades from the upstream palette are remapped onto the active
   accent, so a compiled file cannot keep a stale accent colour.

Also add the site to the priority list in `sync_userstyles` if it is a popular
one, and mention it in [Browser](../usage/browser.md) if it needs special notes.

## Add a package

- One-off packages: `pkgs/custom.nix`.
- Permanent tooling: the matching file in `pkgs/categories/`.
- A whole new category: add a `pkgs/categories/<name>.nix` and reference it in
  `pkgs/categories.nix`; the `pwnbox.packages.toolset.<name>` option is created
  automatically.

## Add a bar style

1. Create `dotfiles/config/quickshell/BarStyle<NN>.qml` (copy an existing one).
2. Add its geometry to `dotfiles/config/quickshell/BarStyles.js`. **This is the
   single source of truth.** The bar and the calendar both read it.
3. Add an entry to `bar_styles` in `dotfiles/scripts/pwnbox-theme`:
   `"<id>|<Label>"`.
4. Add a preview `dotfiles/config/quickshell/previews/<id>.png`.
5. Rebuild, then choose it from `ALT + S → Style`.

Keep the `height`, `exclusive`, `top`/`bottom` and `clock` fields accurate so
the calendar and exclusive zone stay correct.

## Add a font

1. Add the package to `modules/nixos/desktop/fonts.nix`.
2. Add its family name to `font_choices` in
   `dotfiles/scripts/pwnbox-theme`.
3. If it should be the default, also update the `named` defaults in
   `fontconfig.defaultFonts` and `modules/home/gtk.nix`.

## Add live theming for an app

Live updates work best when the app watches a file we can rewrite. The pattern
used by Spotify, Equibop and Telegram is:

1. Keep a managed **base** config in the flake.
2. Generate the app's real config from the palette (and fonts) at runtime.
3. Detect the current theme change from `pwnbox-theme`'s `apply_borders`
   (which is called on every switch).
4. If the app supports file watching, rewrite the file in place; otherwise push
   the change however the app supports it (AyuGram reads its `monoFont` only
   at startup, so `sync_telegram_fonts` restarts it when the font changed and
   the app is running).

Add the app to `docs/usage/apps.md` when you do.

## The IDA theme

- `dotfiles/config/wal/templates/pwnbox-ida-theme.css` is the pywal
  template (flat backgrounds, borders = background lightened 12% via
  pywal's `{background.lighten(12)}` marker). `dotfiles/config/wal/
  monochrome/ida-theme.css` is the pre-rendered monochrome seed — keep
  both in sync when editing.
- Non-palette braces in the template are escaped as `{{…}}` (pywal passes
  them through) and unescaped by `sync_ida_theme` in
  `dotfiles/scripts/pwnbox-theme`.
- The plugin in `dotfiles/ida/plugin/` is the [catppuccin-ida
  runtime](https://github.com/Pistonight/catppuccin-ida) adapted for the
  `pwnbox` theme (icon swapping removed; IDA's own icons are kept).
- `dotfiles/ida/icons/` holds SVG templates; `sync_ida_theme` tints them
  with the palette at apply time.
- `dotfiles/scripts/pwnbox-ida-reg` patches `~/.idapro/ida.reg`
  (theme name + fonts, CRC re-sealed).

## Stremio Enhanced

- `pkgs/apps/media/stremio-enhanced.nix` wraps the upstream AppImage with
  `appimageTools.wrapType2` and pins the streaming server
  (`serverVersion` + its hash). The package ships a `nix-update` script for
  the AppImage; bump `serverVersion` by hand
  (`dl.strem.io/server/<version>/desktop/server.js`, version from the
  stremio-service `Cargo.toml`).
- The theme is generated by `sync_stremio` in `dotfiles/scripts/pwnbox-theme`
  (pywal palette first, pwnbox cache fallback, flat backgrounds, application
  font, UI radius). It writes
  `~/.config/stremio-enhanced/themes/pwnbox.theme.css`, which Stremio reads
  at startup — no live reload.
- Fonts inside the AppImage's FHS sandbox come from `extraPkgs` and the
  bundled `FONTCONFIG_FILE`; `overlays/default.nix` passes the two custom
  pwnbox font packages via `extraFonts`.

## Signal

- Signal Desktop has no upstream custom theme support, so the overlay
  (`pkgs/apps/messaging/signal-desktop.nix`) rebuilds the nixpkgs package with an extra
  `postInstall` step: unpack `app.asar`, append `pkgs/apps/messaging/signal-loader.js` to
  `bundles/main.js` (the Electron main process bundle), repack. Keep the
  loader self-contained (no imports) and resilient — it runs in the main
  process of every Signal window.
- The loader reads `~/.config/Signal/theme.css`, injects it with
  `webContents.insertCSS` on every window (`browser-window-created` +
  `did-finish-load`) and re-applies it when the file changes
  (`fs.watchFile`), so theme and font switches apply live.
- `sync_signal` in `dotfiles/scripts/pwnbox-theme` generates that file from
  the palette: the Axo `--axo-color-*` design tokens (surfaces, labels,
  fills, borders, bubbles) map onto the pywal ramp, semantic slots use the
  `red` / `green` / `yellow` / `accent` palette entries, and the application
  font goes into `--font-sans` / `--font-mono`. Signal 8.x moved to these
  Axo tokens (compiled into `stylesheets/tailwind.css`); if upstream
  changes tokens, update the token list in `sync_signal`.

## Element

- Same mechanism as Signal: the overlay (`pkgs/apps/messaging/element-desktop.nix`) repacks
  `app.asar` with `pkgs/apps/messaging/element-loader.js` appended to
  `lib/electron-main.js`. Element's main process is ESM
  (`"type": "module"`), so the loader uses dynamic `import()` + top-level
  await instead of `require`.
- The webapp ships as a real copy of `element-web-unwrapped` with
  `show_labs_settings = true` merged into `config.json` (the nixpkgs
  `element-web.override { conf }` wrapper produces a symlink farm that
  electron-builder's asar step refuses to pack).
- The loader reads `~/.config/Element/theme.css` and injects it live, exactly
  like the Signal loader (insertCSS + `fs.watchFile`).
- `sync_element` generates that file: the Compound design tokens
  (`--cpd-color-*` semantics plus the raw `gray`/`green` ramps the element
  theme css references directly) map onto the palette, and the application
  font goes into `--cpd-font-family-sans` / `--cpd-font-family-mono`. If
  Element/Compound renames tokens, update the token list in `sync_element`.
  It also writes the `element-pwnbox.json` custom theme (name "Pwnbox") for
  the theme picker.

## Wire

- Same mechanism as Signal: the overlay (`pkgs/apps/messaging/wire-desktop.nix`) repacks
  `app.asar` with `pkgs/apps/messaging/wire-loader.js` appended to the CJS webpack bundle
  `electron/dist/main.js`.
- The webapp is loaded from the Wire CDN into a remote `<webview>`, so the
  loader injects into every webContents via `web-contents-created` (which
  also fires for webview guests), not just BrowserWindows. It reads
  `~/.config/Wire/theme.css` and applies it live (`fs.watchFile`).
- `sync_wire` generates that file: Wire's CSS variables (`--gray-*` ramp,
  foreground/background fades, framework slots, the accent block, `--*-500`
  color triples) map onto the palette, plus the application font and UI
  radius. If Wire's webapp changes its variable set, update the token list
  in `sync_wire`.

## SimpleX Chat

- SimpleX is a Compose-multiplatform AppImage: no DOM to inject CSS into and
  no live theme reload. Themes are YAML overrides
  (`~/.config/simplex/themes.yaml`) selected through `CurrentTheme` /
  `CurrentThemeIds` in `~/.config/simplex/settings.properties`; both are
  only read at startup.
- `sync_simplex` merges a `pwnbox` override (fixed `themeId`, base `DARK`)
  into `themes.yaml` — preserving other themes — and rewrites only the three
  theme-selection keys in `settings.properties`. Because the app caches both
  in memory, a running instance is stopped first, then relaunched.
- Fonts: the app hardcodes the bundled Inter files
  (`fonts/Inter-*.ttf` inside `common-desktop-*.jar`). The pwnbox launcher
  (`pkgs/apps/messaging/simplex-launcher.sh`, installed as `simplex-chat-desktop`) keeps a
  writable copy of the extracted AppImage under
  `~/.local/share/pwnbox/simplex`, swaps those entries for the current
  application font (resolved through `fc-match`) and runs the copy inside the
  upstream FHS wrapper via `APPIMAGE_DEBUG_EXEC`. The jar is only repacked
  when the font setting changes.

## Testing

- Syntax-check the shell helpers:
  `bash -n dotfiles/scripts/pwnbox-theme scripts/*.sh`
- Parse the Nix modules: `nix-instantiate --parse modules/home/dotfiles.nix`
- Build without activating: `./scripts/install.sh build`
- Try it for one boot: `./scripts/install.sh test`

## Style guidelines

- Keep generated files out of the flake; only bases live there.
- Prefer `run` and `entryAfter` in activation scripts so changes are
  idempotent.
- When hiding UI (scrollbars, upsells), match by stable attribute/substring and
  keep the rule defensive so a client update cannot break layout.
